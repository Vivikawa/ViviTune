# ViviTune 2 — новый интерфейс на Avalonia (этап 1: Windows)

Дата: 2026-10-18. Основа: `2026-10-04-vivitune-design.md` (что делает программа и как устроен конфиг
sing-box). Этот документ описывает только то, что меняется.

## Зачем

ViviTune v1 работает (Discord с голосом и стримом и браузер ходят через SOCKS5 роутера), но окно
состоит из голых стандартных элементов WinForms. Пользователь хочет современный тёмный вид «как
Hiddify», видеть скорость трафика через прокси, а позже запускать программу и на Arch Linux.
WinForms и WPF привязаны к Windows, поэтому окно переезжает на Avalonia (C#, кроссплатформенная).

Этап 1 (этот документ): новое окно на Windows. Этап 2 (отдельная спецификация потом): Arch Linux.

## Цели

1. Тёмное окно с боковым меню и четырьмя страницами: Главная, Приложения, Лог, Настройки
   (раскладка «B», макет: `assets/2026-10-18-ui-mockup.html`).
2. На Главной: большая круглая кнопка подключения, статус, скорость отдачи и загрузки **только
   трафика через прокси** с мини-графиками.
3. На странице Приложения: добавление из списка **запущенных сейчас программ** (иконки, поиск),
   плюс «Выбрать .exe вручную» для незапущенных; у каждого приложения переключатель «вкл/выкл» и
   крестик «удалить».
4. Всё, что работает в v1, продолжает работать так же (см. «Сохраняем»).

## Не цели (этап 1)

- Linux. Но платформенный код держим в отдельных файлах (см. «Под Linux потом»), чтобы этап 2 не
  требовал переписывать окно.
- Скорость всего интернета на ПК, скорость по каждому приложению отдельно.
- Светлая тема, трей, автозапуск, профили, логин и пароль прокси, правила по доменам,
  автообновление sing-box.

## Анти-цели (провал, даже если «формально работает»)

- Сломать то, что сейчас работает: Discord-голос и стрим через прокси, DNS по TCP, исключение
  адреса прокси, Job Object, проверка прокси перед стартом.
- Потерять настройки пользователя: существующий `settings.json` формата v1 должен открыться.
- Окно, которое подвисает во время проверки прокси, перезапуска sing-box или опроса скорости.

## Решения пользователя

- Вид «как Hiddify», тёмный.
- Раскладка B: боковое меню + страницы.
- Скорость только для трафика через прокси.
- Добавление приложений: список запущенных программ с иконками и поиском + ручной выбор `.exe`.
- Сначала Windows, Linux вторым этапом; фреймворк окна не WPF.
- Подтвердил весь описанный ниже набор поведения («Всё верно»), включая переключатели у
  приложений и автоматический перезапуск sing-box при изменении списка во время работы.

## Решения, принятые мной (можно оспорить)

- **Фреймворк:** Avalonia 12.x (последняя стабильная на момент сборки, версию зафиксировать в
  csproj), встроенная тема Fluent в тёмном варианте + свои стили по палитре ниже. Шрифт Inter
  (пакет `Avalonia.Fonts.Inter`). Сторонние наборы контролов не нужны.
- **Платформа .NET:** .NET 10 (LTS). .NET 8 заканчивает поддержку в ноябре 2026. Нужно поставить
  .NET SDK 10 (сейчас стоит 8.0.425); спросить пользователя перед установкой.
- **Сборка для пользователя:** `dotnet publish` self-contained, `win-x64`, один `ViviTune.exe`
  рядом с `sing-box.exe`. Ничего ставить пользователю не нужно.
- **Проект:** WinForms-проект `src/ViviTune` переводится на Avalonia на месте (тот же путь, тот же
  `ViviTune.exe`). `MainForm.cs` и WinForms-`Program.cs` удаляются. Тесты `src/ViviTune.Tests`
  переводятся на тот же `net10.0` и остаются консольными с `Check` (без тестовых фреймворков).
- **JSON:** `JavaScriptSerializer` (есть только в .NET Framework) заменяется на `System.Text.Json`.
- **Без MVVM-фреймворков** (ReactiveUI, CommunityToolkit не нужны): код страниц в code-behind или
  простой класс-состояние с `INotifyPropertyChanged`. На выбор строителя, если не тянет
  зависимость.

## Сохраняем из v1 без изменений поведения

- Конфиг sing-box из `ConfigBuilder` (TUN v4+v6, `process_name` → `proxy`, `final: direct`,
  исключение `<proxy-ip>/32|/128`, `proxy-dns` по TCP через прокси, лог `warn`).
- `ProxyProbe` (TCP + SOCKS5 + UDP ASSOCIATE, никогда не бросает исключений).
- `Runner` (sing-box в Job Object с kill-on-close, события `Line`/`Exited`).
- Манифест `requireAdministrator`, один экземпляр (named Mutex), `settings.json` и `config.json`
  рядом с exe, sing-box 1.12.12.
- Поток запуска: проверка прокси → нет UDP = только предупреждение → конфиг → запуск.
  Неожиданный выход sing-box показывается как ошибка.

## Что меняется в ядре

### Settings

- Приложение теперь запись `{ Path, Enabled }` вместо строки пути.
- Загрузка читает и старый формат v1 (`"Apps": ["C:\\...\\Discord.exe", ...]`): каждая строка
  становится `{Path, Enabled: true}`. Сохраняем уже в новом формате.
- `Validate()`: как раньше, но «хотя бы одно **включённое** приложение».
- `ProcessNames()`: только включённые, остальная логика (имя файла, без дублей без учёта регистра,
  без `sing-box.exe`) прежняя.

### ConfigBuilder

- Добавляет `experimental.clash_api`: `external_controller: "127.0.0.1:<свободный порт>"`,
  `secret: <случайная строка на каждый запуск>`. Порт и секрет приходят параметрами, чтобы функция
  осталась чистой и тестируемой. Clash API есть в официальной сборке 1.12.12 (тег
  `with_clash_api`, проверено `sing-box version`).
- Остальное без изменений. Сгенерированный конфиг должен проходить `sing-box check`.

### Новый: TrafficMeter (скорость через прокси)

- Раз в секунду `GET http://127.0.0.1:<порт>/connections` с заголовком
  `Authorization: Bearer <secret>`. Ответ — список текущих соединений с суммарными `upload`,
  `download` и цепочкой `chains`.
- Учитываем только соединения, в `chains` которых есть `proxy`. Скорость = сумма приростов
  `upload`/`download` по id соединения относительно прошлого опроса. Новое соединение считается от
  нуля. Соединения, закрытые между опросами, теряют последнюю долю секунды: скорость примерная, это
  приемлемо.
- Расчёт приростов — чистая функция (два снимка → скорость), под неё автотест.
- Опрос не в UI-потоке; ошибки опроса (sing-box ещё стартует, перезапуск) просто дают 0 и не
  попадают в лог чаще раза за запуск.
- История на графиках: последние 60 значений (60 секунд).

### Новый: список запущенных программ (Windows)

- Уникальные `.exe` из `Process.GetProcesses()` с доступным путём к файлу. Исключаем файлы из
  `%WINDIR%`, сам `ViviTune.exe`, `sing-box.exe` и уже добавленные. Сортировка по имени, поиск по
  имени без учёта регистра.
- Имя для показа: `FileVersionInfo.FileDescription`, если есть, иначе имя файла без `.exe`.
- Иконка: `System.Drawing.Icon.ExtractAssociatedIcon` → PNG → Avalonia `Bitmap`. Тот же способ для
  иконок в списке выбранных приложений. Нет иконки — плашка с первой буквой (как в макете).
- Это Windows-только код, в отдельном файле.

### Перезапуск при изменении списка во время работы

- Включение, выключение, добавление или удаление приложения при подключении: собрать новый конфиг
  и перезапустить sing-box (Stop → Start) **без** повторной проверки прокси. Быстрые изменения
  подряд склеиваются (ждём ~1 с после последнего изменения). Пользователю — строка в логе и
  короткое состояние «Перезапуск…» у кнопки; это остановка «по желанию», а не ошибка.
- Если после изменения не осталось ни одного включённого приложения — отключиться (правило без
  приложений матчило бы весь трафик).
- Настройки прокси (IP, порт) во время подключения не редактируются, как в v1.

## Интерфейс

Макет: `assets/2026-10-18-ui-mockup.html` (Главная + Приложения), варианты раскладки:
`assets/2026-10-18-ui-layout-options.html` (выбран B). Макет задаёт вид, а не пиксели.

### Палитра и стиль (из макета)

| Токен | Цвет | Где |
|---|---|---|
| фон окна | `#0e1120` | основа |
| фон меню | `#0b0d1a` | боковая панель |
| карточка | `#171b2e` | карточки скорости, строки приложений |
| линия | `#252a44` | рамки, разделители |
| текст | `#e8eaf6` | основной |
| вторичный | `#8a90b4` | подписи, иконки меню |
| акцент 1 | `#22d3ee` | загрузка, активный пункт меню |
| акцент 2 | `#8b5cf6` | отдача; градиент акцент 1 → акцент 2 на кольце кнопки и переключателях |

| ошибка | красный на выбор строителя | текст ошибки |

Скругления 10–14 px, без лишних рамок. Заголовок окна тёмный (системный в тёмном режиме или
своя область заголовка — на выбор строителя). Окно с изменяемым размером, минимальный ~760×520.

### Боковое меню

Иконки: Главная, Приложения, Лог, Настройки. Активный пункт подсвечен акцентом 1.

### Главная

- Плашка вверху: `SOCKS5 · <ip>:<port>`.
- Круглая кнопка ~130 px со значком питания. Состояния:
  - **Отключено:** серое кольцо, без свечения. Нажатие → проверка.
  - **Проверка / Перезапуск:** кольцо крутится, кнопка неактивна.
  - **Подключено:** кольцо-градиент со свечением. Нажатие → отключение.
- Под кнопкой статус: «Отключено» / «Проверяю прокси…» / «Подключено» (зелёным). Строкой ниже при
  подключении: время работы, `UDP ✓` или `UDP ✗`, число включённых приложений.
- Ошибки (прокси недоступен, sing-box упал, не найден `sing-box.exe`, нет включённых приложений)
  — текстом под кнопкой. Предупреждение «UDP не работает» — тоже здесь, а не только в логе.
- Две карточки: «↑ Отдача через прокси» и «↓ Загрузка через прокси». В каждой — текущая скорость
  (Б/с, КБ/с, МБ/с с одним знаком после запятой) и мини-график за 60 с. Без подключения — нули.

### Приложения

- Заголовок «Приложения через прокси». Строки: иконка, имя, имя файла мелко, переключатель,
  крестик.
- «＋ Добавить» открывает выпадающую панель: поиск, раздел «Запущены сейчас» (иконка, имя,
  «＋»), внизу «Выбрать .exe вручную…» (диалог выбора файла). Добавленное сразу включено.
- Пустой список — подсказка «Добавьте приложение, трафик которого пойдёт через прокси».

### Лог

То, что сейчас: строки sing-box уровня `warn` и сообщения ViviTune, не больше 500 строк, прокрутка
держится внизу. Моноширинный шрифт.

### Настройки

IP и порт прокси, проверка на ходу (как `Validate`), сохранение автоматически. Неактивны при
подключении. Внизу мелко: версия ViviTune и sing-box.

## Под Linux потом (этап 2, сейчас только не мешать)

Windows-специфичное держим за узкими границами, в отдельных файлах: `Runner` (Job Object),
извлечение иконок и список процессов, манифест администратора, путь к `sing-box.exe`. Окно,
`Settings`, `ConfigBuilder`, `ProxyProbe`, `TrafficMeter` не должны знать про Windows. Абстракции
«на будущее» не вводим — просто не смешиваем.

## Проверка

- Перенести все 22 существующих теста на `net10.0`, все должны проходить.
- Новые автотесты: чтение `settings.json` старого формата; `ProcessNames` и `Validate` учитывают
  только включённые приложения; в конфиге есть `clash_api` с переданными портом и секретом;
  расчёт скорости из двух снимков (только `proxy`, новое соединение, исчезнувшее соединение).
- `sing-box check` на сгенерированном конфиге.
- Проверка жизненного цикла sing-box (старт, `Stop()`, жёсткое убийство родителя) тем же способом,
  что 2026-10-18 (временный проект с повышением прав).
- Ручная проверка пользователем: вид всех четырёх страниц; Discord с голосом через прокси; скорость
  растёт при загрузке через выбранное приложение и стоит на нуле от остальных; добавление из
  списка запущенных; выключение приложения во время работы перезапускает sing-box и трафик этого
  приложения идёт напрямую; старый `settings.json` подхватился.

## Оставлено строителю

Структура файлов и классов окна, способ привязки данных (без MVVM-фреймворков), анимация кольца,
точный вид графика, иконки меню (любые свободные или встроенные), выбор свободного порта для Clash
API, способ склейки быстрых изменений.
