# ViviTune — дизайн

Дата: 2026-10-04

## Цель

Windows-программа для личного использования. Пользователь один раз вводит адрес SOCKS5-прокси
(сейчас `192.168.1.1:1818`, роутер с «Подкопом»), выбирает приложения, и весь сетевой трафик
(TCP и UDP) этих приложений идёт через прокси. Остальной трафик системы идёт напрямую.

## Критерии успеха

- Выбранное приложение работает через прокси без настроек внутри него (в том числе игры,
  голосовая связь и программы, игнорирующие системный прокси).
- Другие приложения идут напрямую, их IP не меняется.
- DNS-запросы выбранных приложений идут через прокси (без утечек).
- Адрес прокси вводится один раз и сохраняется.

## Допущения

- Прокси без логина и пароля.
- Нужны права администратора (TUN-адаптер).
- Поддержку `UDP ASSOCIATE` у прокси мы не знаем, программа проверяет её сама и предупреждает.

## Решение

Обёртка над [sing-box](https://github.com/SagerNet/sing-box) (зафиксированная версия **1.12.12**).
Программа генерирует конфиг и запускает `sing-box.exe` с TUN-адаптером. Собственного сетевого
кода нет.

Отвергнуты: инъекция DLL (Winsock-хуки; ломается на античитах и защищённых процессах) и
собственный движок на WinDivert (на порядок больше кода при тех же результатах).

## Стек

C# WinForms, .NET Framework 4.8 (есть в Windows 10/11, ничего устанавливать не нужно).
Рядом с `ViviTune.exe` лежит `sing-box.exe`.

## Компоненты

1. **Settings**: `ip`, `port`, список `.exe` в `settings.json` рядом с программой.
2. **ConfigBuilder**: чистая функция «Settings → JSON конфиг sing-box» (см. ниже).
3. **Runner**: запускает и останавливает `sing-box.exe`, выводит его лог, завершает процесс при
   закрытии программы (Windows Job Object, чтобы дочерний процесс не оставался при падении).
4. **UI**: поля IP и порт, список приложений («Добавить…» через диалог выбора файла, «Удалить»),
   кнопка «Старт/Стоп», строка статуса, окно лога. Манифест `requireAdministrator`.

## Конфиг sing-box (генерируется ConfigBuilder)

- `inbounds`: `tun` с `auto_route: true`, `address: ["172.19.0.1/30"]`, `strict_route: false`.
- `outbounds`: `socks` (тег `proxy`, `server`/`server_port` из настроек, `version: "5"`),
  `direct` (тег `direct`).
- `route.rules` (по порядку):
  1. `{"action": "sniff"}`
  2. `{"protocol": "dns", "action": "hijack-dns"}`
  3. `{"ip_cidr": ["<proxy-ip>/32"], "outbound": "direct"}` (исключает петлю к самому прокси)
  4. `{"process_name": [<имена выбранных .exe>], "outbound": "proxy"}`
- `route.final: "direct"`, `route.auto_detect_interface: true`,
  `route.default_domain_resolver: "local"`.
- `dns.servers`: `local` (`type: local`) и `proxy-dns` (`type: tcp`, `server: 1.1.1.1`,
  `detour: "proxy"`).
- `dns.rules`: `{"process_name": [<те же имена>], "server": "proxy-dns"}`; DNS остальных процессов
  идёт через `local`.

Совпадение идёт по имени файла (`chrome.exe`), поэтому многопроцессные приложения
(браузеры, Discord) покрываются целиком. Минус: одноимённый `.exe` из другой папки тоже попадёт
в правило. Для личного использования принимается.

## Поток запуска

1. Валидация полей (IP, порт 1–65535). Пока не валидно, «Старт» неактивен.
2. Проверка прокси: TCP-соединение + SOCKS5-рукопожатие. Не вышло: сообщение об ошибке, sing-box
   не запускается.
3. Проверка `UDP ASSOCIATE`. Не поддерживается: предупреждение «UDP через этот прокси не работает:
   игры и голосовая связь могут не заработать». Запуск при этом не блокируется.
4. ConfigBuilder пишет `config.json`, Runner запускает `sing-box.exe run -c config.json`.

## Ошибки

- `sing-box.exe` не найден или завершился сам: показать последние строки лога, кнопка возвращается
  в состояние «Старт».
- Закрытие или падение программы: Job Object убивает sing-box, TUN-адаптер исчезает.
- Нет прав администратора: манифест вызывает UAC.

## Проверка

- Один автотест на ConfigBuilder: для заданных ip, port и списка `.exe` проверяется наличие правила
  `process_name` → `proxy`, `final: direct`, исключение `<proxy-ip>/32` и DNS-правило.
- Ручная проверка: добавить браузер, открыть сайт с показом IP. Должен быть IP прокси. В другом
  браузере IP остаётся прежним. Если проверка UDP прошла, проверить голосовую связь или игру.

## Не делаем (YAGNI)

Профили, автозапуск, значок в трее, логин и пароль прокси, правила по доменам, автообновление
sing-box, сопоставление по полному пути.
